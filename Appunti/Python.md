## Introduzione
Python è un linguaggio di programmazione interpretato, ovvero in cui il codice non viene prima tradotto interamente in linguaggio macchina, ma le singole istruzioni vengono eseguite, dall'interprete Python (CPython), riga per riga. Ciò che fa CPython è tradurre il codice in un "byte code" (file .pyc), ovvero uno codice generato appositamente per una macchina virtuale, la PVM (Python Virtual Machine).
Python, in quanto orientato agli oggetti, manipola i cosiddetti data objects, ovvero oggetti che hanno un tipo, che può essere scalare e non-scalare, dove per non-scalare si intendono oggetti con una struttura interna accessibile. Le stringhe sono tipi di oggetti particolari, che sono per definizione non-scalari (dato che sono letteralmente array di caratteri), ma vengono trattati come scalari (non si può modificare con una normale assegnazione un singolo carattere di una stringa).
Una funzione in Python è composta da nome, parametri, docstring opzionale, corpo e valore di ritorno (se non specificato, una funzione in Python ritorna sempre None).
Per scope di una variabile si intende il mapping tra il nome della variabile e l'oggetto a cui punta, che può cambiare in base alla funzione in esecuzione. 

## Moduli e Package
In Python le definizioni di funzioni e variabili non sono salvate all'uscita dell'interprete, quindi arrivano in nostro soccorso i moduli, che permettono di eseguire istruzioni come script eseguibili (infatti sono proprio dei normali file .py), importandoli tramite keyword import (nel momento in cui l'interprete esegue l'import, vengono eseguite tutte le dichiarazione e definizioni del modulo importato). Per definire delle funzionalità di un modulo che non vanno eseguite all'importazione, queste si possono inserire nella variabile globale \_\_main\_\_, così che vengano eseguite solo quando è il modulo stesso ad essere eseguito dall'utente. CPython cerca i moduli importati in determinati luoghi specifici, nel seguente ordine: 
directory corrente -> elenco delle directory nel PYTHONPATH -> percorso predefinito (in base all'installazione).
Esiste anche una libreria standard di moduli Python, in cui sono contenuti moduli che svolgono operazioni importanti ma non facenti parte del nucleo di Python, come ad esempio il modulo sys, che grazie alla sua variabile argv permette di fornire parametri ad un programma python direttamente dall'esecuzione, specificandoli dopo il nome del programma (python programma.py arg1 arg2 ...).
I moduli in Python sono organizzati in Packages, memorizzati in directory, dove ogni directory contiene un file \_\_init.py\_\_, che istruisce l'interprete di trattare la directory come fosse un package e può essere vuoto oppure contenere delle istruzioni di inizializzazione per il package.

## Tuple, Liste e Dizionari
Le strutture dati principali di Python sono Tuple, Liste e Dizionari, indicate rispettivamente con (), 
\[\] e {}.
Le Tuple sono una sequenza **ordinata** di elementi eterogenei che non possono cambiare, quindi una tupla è immutabile. 
Una Lista è una sequenza **ordinata** di informazioni, accessibile tramite indice. Anch'essa può contenere elementi eterogenei, ma non è buona norma farlo. Gli elementi di una lista possono cambiare, quindi è mutabile. Su una lista si possono effettuare varie operazioni: add, extend, remove, sort, reverse...
Dichiarando una  lista, e poi assegnando il nome di questa lista ad un'alta variabile, si va a creare un alias, e ogni modifica fatta sull'alias si andrà a rispecchiare sulla lista originale (e viceversa), se si vuole creare una nuova lista partendo da una già esistente, bisogna usare l'operatore \[\:\].
Il terzo tipo di struttura dati è il Dizionario, ovvero una struttura composta da elementi associati ad un identificativo (una coppia chiave/valore). I valori possono essere di qualsiasi tipo, possono essere duplicati e addirittura possono essere altre strutture dati (un dizionario di dizionari è possibile), mentre le chiavi devono essere uniche ed immutabili. Né le chiavi né i valori sono ordinati.

## Parametri
In Python tutto è un oggetto, con cui si può interagire tramite i riferimenti, e ciò vale anche per il passaggio di parametri: passando un parametro ad una funzione, il riferimento contenuto nel parametro attuale è copiato in quello formale, e se si tratta di un oggetto mutabile, ogni modifica del parametro formale si riflette su quello attuale.
Per passare un numero variabile di argomenti si può dichiarare tra i parametri nella firma della funzione il parametro \*args (dev'essere l'ultimo parametro della firma), Inoltre, è possibile per il chiamante specificare quale parametro attuale rappresenta quale parametro formale tramite i keyword arguments, ed inoltre è possibile usare il parametro \*\*kwargs per passare un numero variabile di di keyword arguments.

## File e Eccezioni
Quando viene eseguito un programma Pyhon si creano 3 oggetti file: sys.stdin, sys.stdout e sys.stderr; che rappresentano i flussi di dati standard che collegano il programma al terminale.
E' possibile utilizzare l'istruzione with per acquisire risorse e rilasciarle automaticamente al termine del loro utilizzo, questa può essere usata sia per file che per lock.
Le funzioni principali sui file sono open, write, readlines e seek.
Per gestire i file si fa uso del modulo os, che permette di creare, rimuovere e rinominare file del filesystem.
Quando una funzione produce delle condizioni non attese si genera un'eccezione, le eccezioni possono essere gestite tramite blocco try/except/else/finally. Si può anche sollevare un'eccezione manualmente tramite l'istruzione raise. Infine, si possono usare le asserzioni per essere sicuri che l'esecuzione sia come attesa, quindi si può usare l'istruzione assert, che verifica la condizione attesa e se fallisce solleva un AssertionError.

## OOP
Python è Object-Oriented, quindi ogni tipo di dato rappresenta una classe. Gli oggetti possono essere istanziati, manipolati e distrutti (esplicitamente o lasciando il compito al garbage collector).
Una classe può essere implementata tramite la keyword class, seguita da nome e eventuali relazioni con altre classi. I dati e le procedure che appartengono ad una classe sono detti attributi e metodi. Il costruttore in Python è un metodo chiamato \_\_init\_\_, che prende come primo parametro self, che rappresenta l'istanza della classe.
Un altro metodo particolare è \_\_str\_\_ che è utilizzato per permettere l'uso di un oggetto di una classe in una print. Ci sono molti altri metodi che si possono overridare per adattare il comportamento di altri operatori speciali, come \_\_add\_\_ per la somma o \_\_eq\_\_ per l'uguaglianza.
Altri metodi importanti sono i getter e setter che sono utilizzati per implementare il concetto di information hiding all'interno del programma.
Una superclasse è una classe da cui altre classi, le sottoclassi, ereditano attributi e metodi. Una sottoclasse può ereditare da più superclassi (ereditarietà multipla), ma questa possibilità introduce un problema noto come il Diamond Problem: se una classe eredita da due classi che overloadano lo stesso metodo di una superclasse, quale metodo verrà usato se invocato dalla prima classe? Python risolve il problema dando la priorità in base all'ordine di ereditarietà.
Le classi in Python possono anche avere delle variabili statiche, ovvero condivise tra tutte le istanze della classe. I metodi statici invece sono metodi di una classe che possono essere invocati senza averne istanziato un oggetto.
In Python ogni eccezione è un oggetto della classe BaseException (o di una classe che eredita da quella, tra cui le quattro principali sottoclassi ovvero SystemExit, KeyboardInterrupt, GeneratorExit e Exception).
Il polimorfismo in Python consente di avere sottoclassi con metodi omonimi alle superclassi, lasciando poi all'interprete il compito di scegliere il più adatto a run-time. La caratteristica principale è che consente ciò è il duck typing (un tipo di tipizzazione dinamica), che fa uso di late binding e dynamic dispatch per identificare di che tipo è un oggetto, in base alla presenza di metodi o di proprietà varie.
Una classe che contiene almeno un metodo astratto (ovvero un metodo senza implementazione, quindi solo la firma) è detta classe astratta, mentre se tutti i metodi sono astratti, allora è un'interfaccia. Le classi astratte (e quindi le interfacce) non possono essere istanziate, ma sono solo dei "modelli" per altre classe che ereditano da esse. In Python l'infrastruttura che definisce il comportamento di una classe astratta è data dal modulo abc, che va sempre ereditato da qualsiasi classe astratta. Di questo modulo bisogna anche usare il decoratore @abc.abstractmethod per indicare che un metodo è astratto.
Per quanto riguarda le interfacce, ci sono due approcci principali, informale e formale. Le interfacce informali sono quelle più semplici che sfruttano la natura dinamica di Python per definire metodi astratti da overridare, ma senza obbligare le sottoclassi ad effettuare questo overriding; un'interfaccia formale invece sfrutta anch'essa l'eredità da abc e il decoratore @abc.abstractmethod per obbligare le sottoclassi ad effettuare l'overriding di tutti i metodi.

## Programmazione Concorrente
In Python abbiamo a disposizione due moduli per gestire al concorrenza: threading e multiprocessing.
Il modulo threading fornisce un'interfaccia di alto livello per il multihtreading, tramite varie classi, ad esempio la classe Thread, le cui istanze rappresentano un flusso di controllo separato da quello principale (il Main Thread). I due metodi principali di creare un Thread sono istanziando direttamente un oggetto di Thread (passando un callable object come parametro) oppure creando una classe che estende Thread e overrida il metodo run(). Un thread può essere contrassegnato come daemon, e ciò vuol dire che il programma principale non dovrà attendere che esso si concluda per terminare, ma verrà interrotto automaticamente alla terminazione del processo padre. E' possibile usare la classe local per definire degli attributi di un oggetto thread i cui valori sono esclusivi al singolo thread in esecuzione, nonostante condivida lo spazio di memoria con il padre e i fratelli.
Per la sincronizzazione viene utilizzata la classe Lock, i cui oggetti possono trovarsi in uno di due stati: locked o unlocked. Di base è unlocked, ma quando un thread lo acquisisce diventa locked, tornando unlocked al momento del rilascio.
Per gestire l'acquisizione e il rilascio si possono o usare le primitive acquire e release oppure, preferibilmente, lo statement with.
Un'alternativa al Lock è il RLock, ovvero Reentrant Lock, che può essere acquisito più volte dallo stesso thread, avendo a differenza di un Lock classico anche una memoria su chi l'ha acquisito è in grado di "accettare" la riacquisizione da parte dello stesso thread (incrementando un contatore interno che indica il numero di acquisizioni), è utile per gestire il problema del self-deadlock.
La classe Condition implementa una condition variable, ovvero un oggetto che rappresenta una condizione che uno o più thread possono controllare e restare in attesa finchè essa non si verifica (ovvero finchè non vengono notificati da un altro thread). Ad ogni cv è associato un Lock (che di default è reentrant, ma può anche essere classico). Fornisce i metodi wait, wait_for, notify e notify_all, che rispettivamente mettono i thread in attesa della notifica o della condizione e notificano n o tutti i thread in attesa su quella cv.
La classe Semaphore introduce l'oggetto semaforo, che gestisce un contatore interno che viene decrementato ad ogni acquire e incrementato ad ogni release, e quando arriva a zero blocca il thread chiamante finché non viene incrementato da un altro thread.
La classe Event fornisce un meccanismo di comunicazione tra thread: è possibile istanziare un oggetto event che ha un flag interno che può essere Set o Clear (True o False), e tramite il metodo is_set è possibile controllarne lo stato (oppure porre un thread in attesa del set tramite l'apposita wait).
Python utilizza un meccanismo, noto come Global Interpreter Lock (GIL) per assicurarsi che solo un thread alla volta possa eseguire bytecode, rendendo nell'effettivo l'esecuzione di thread non parallela, creando un grosso collo di bottiglia per i task cpu-bound.
Il modulo multiprocessing supporta lo spawning (in windows, oppure il forking in linux) di processi multipli, aggirando così il problema del GIL (che agisce solo sui thread), dato che crea più processi ognuno con il suo interprete (CPython) e il suo GIL. I metodi principali di avvio di un processo sono spawn, fork e forkserver. Spawn è il default per Windows e MacOS, in cui il padre avvia un nuovo Interpreter Process ed il figlio eredita solo le risorse necessarie ed esegue il metodo run. Fork è il default su Linux, tramite cui il figlio all'avvio eredita tutte le risorse del padre, ma è considerata unsafe dato che duplica solo il flusso di controllo principale del processo, quindi se il padre aveva dei figli con dei lock acquisiti, questi resterano acquisiti da qualcuno anche nel processo figlio, ma non avendo dei thread figli a sua volta, questo lock non potrà mai essere rilasciato (deadlock). Forkserver invece crea un Server Process, a cui il padre si connette quando necessario e richiede ad esso la fork di un processo nuovo, evitando così di ereditare risorse non necessarie e dato che il Server Process è single-thread, l'uso di fork lì è safe.
Esiste un fork del modulo multiprocessing chiamato multiprocess che sostituisce il serializzatore standard (pickle) con dill, permettendo di passare ai processi paralleli callable più complesse, come ad esempio le funzioni lambda.
Un oggetto della classe Process rappresenta un'entità da eseguire in un processo separato, comportandosi allo stesso modo dei Thread di threading, quindi stessa istanziazione e anche multiprocessing fornisce Lock, RLock, Condition, Semaphore ed Event.
Per scambiare oggetti tra processi ci sono due canali di comunicazione principali: Pipe e Queue, dove Pipe consenta la connessione tra più processi e Queue implementa il problema produttori-consumatori. Una Pipe è una coppia di Connection Objects (gli estremi del tubo) e una Queue è una process shared queue, implementata tramite Pipe e Lock (o semafori).
Gli oggetti Connection della Pipe rappresentano gli estremi del tubo e si si possono utilizzare i metodi send e recv, per inviare e ricevere oggetti da un estremo all'altro.
Quando un processo immette un oggetto in una Queue, viene avviato un thread che trasferisce gli oggetti da un buffer alla Pipe usata per implementare la Queue.
Uno degli strumenti offerto dal modulo multiprocessing per la condivisione di dati è la Shared Memory, rappresentata da oggetti di tipo Value o Array (che quindi sono compatibili con il C). 

## Programmazione su Rete
Internet è la grande rete che si estende in tutto il mondo, basata sul protocollo TCP/IP, è una rete di reti, i cui componenti sono: nodi, collegamenti e router. Ad ogni nodo è assegnato un indirizzo IP (IPv4 e IPv6), che servono a trovare mittenti e destinatari. I dati sono trasmessi tramite pacchetti (IP Datagrams) tramite due protocolli principali: TCP e UDP.
Il protocollo TCP è quello affidabile dei due: è orientato alla connessione, fornisce un flusso di byte full duplex e preserva l'ordine dei pacchetti tramite la ritrasmissione di quelli persi. L'UDP invece è non affidabile, proprio come IP, quindi non ha controlli sull'ordine o possibilità di ritrasmissione.
I Socket sono il meccanismo principale di comunicazione su rete tra processi (anche su macchine differenti). Sono caratterizzati da due elementi: IP e Port.
Per creare e usare Socket in Python si usa il modulo socket, i cui metodi principali sono socket, bind, listen, accept, connect e close. Per scambiare dati su socket TCP si usano send e recv: il Client istanzia una Socket e chiede una connessione tramite connect, una volta ricevuta, può scambiare dati tramite send e recv; il Server invece istanzia anch'esso una socket, effettua il bind per legarla ad una porta e si mette in listen aspettando una connessione, quando arriva effettua la accept (che restituisce una socket che rappresenta il Client e l'indirizzo della Socket lato Client) e instaura così il collegamento con il client, potendo quindi scambiare dati tramite send e recv; una volta finito il da farsi, si effettua la close sull'oggetto Socket.
Per la comunicazione UDP con Socket invece si usano sendto e recvfrom: dato che UDP non è connection-oriented non bisogna instaurare la connessione con connect listen e accept, ma il Client effettua direttamente la sendto specificando indirizzo e porta del server e recvfrom, mentre il server deve anche ovviamente fare la bind sulla porta desiderata.
Per migliorare l'efficienza dei Server, questi si possono rendere multi-thread o multi-processo, ricordando che ogni flusso di controllo, thread o processo che sia, deve sempre avere come parametro la connessione restituita dal metodo accept nel caso di Server TCP oppure l'indirizzo e la porta del mittente e il messaggio ricevuto nel caso di Server UDP.
Il pattern Proxy introduce nel modello di interazione Client-Server un Proxy, che rappresenta un'implementazione del servizio remoto, però locale al Client, dove quindi i meccanismi necessari per la comunicazione (TCP o UDP), sono incapsulati all'interno del codice del Proxy.
